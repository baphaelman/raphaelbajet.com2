# The Comma Pump: interactive article on musical tuning

A scroll- and arrow-key-driven explainer in the same format as Single Cycles (pinned stage that changes as the text advances, builds within steps, progress segments, chapter pills). One file, `public/slop/play/comma-pump.html` (it was `tuning.html` in `~/Desktop/Coding/AIrticles/tuning-explainer` until 2026-11-24): CSS, markup and inline JS, no build step, no libraries (Google Fonts only, with system fallbacks). Its words live in a JSON block, with authorship tracked (see below). The site serves it at `/slop/play/comma-pump.html`, opened from the Slop Zone. This folder holds its notes and tools; run the tools from here.

## Rules from the original brief (keep these)

- **Numbers are computed, never typed.** Every cents value and fraction shown is computed in JS from exact ratios (BigInt fractions, class `Q`), or built by code (appendix tables, stage labels). A text puts a figure in as `{key}`, and each `NUM` entry becomes `Slop.vars[key]`, rendered as a `data-k` span. If you add a figure to the text, write `{key}`, add a `NUM` entry, and add the expected value in `tools/check_numbers.py`. That script fails on any span it doesn't check.
- **Sound is Web Audio synthesis only**, at exact frequencies from ratios. Never use samples. The timbre is a periodic wave of `HARMONICS` partials at 1/n^`ROLLOFF`; pure sines would hide beating. Envelopes are gentle (30 ms attack, steady sustain, ~0.3 s release) so nothing clicks.
- Audio starts only after a user gesture. There is one "Enable sound" control (sound bar, bottom left), a master volume and Stop all. Volume and theme persist in `localStorage` (try/catch, optional).
- Dark and light themes are color tokens on `:root`, read into `COL` for canvas/SVG drawing (`readColors`, `COL.key` changes trigger SVG re-renders). The layout works at phone width. Visuals are SVG or canvas.
- The comma pump (section 3) is the centerpiece and gets the most polish.
- American spelling.

## Text, authorship and edit mode

This follows the AI-rticles standard in `../CLAUDE.md`. Read it first. The parts specific to this article:

- The words live in the `#slop-text` JSON block (groups `hero`, `pure`, `stack`, `pump`, `temper`, `lattice`, `after`, with stage text under each group's `stage`). Card elements carry `data-slop`. Stage text in code goes through `Slop.html(...)`: `pu-sub`, the stack titles, `pr-g` ("the comma goes"), `eqbox`, `te-sub` and the lattice's prompt. Labels stay in code: buttons, chapter pills, readout labels, canvas/SVG labels, legends, table headers and cells, and tuning and interval names.
- When this was converted, all the existing prose became AI text. The inline color spans (`.lo`/`.hi`/`.ju`) were dropped, so authorship colors are the only text colors in prose. Computed figures are `{key}` values and show as data (amber).
- Backticks render as `.r`, the mono ratio style. Formulas that need markup are values: `{etSemi}` is 2<sup>1/12</sup> and `{rolloff}` is the overtone exponent.
- `Slop.start({code: 'r'})` runs before the navigation setup, because segment titles read the headings. `Slop.onChange` re-runs `segTitles`, `eqbox`, `SC.pure.text`, `SC.stack.ui`, `SC.temper.update` and `SC.lattice.readout`. Scroll positions (`stopY`, `detect`) are measured live, so they follow text changes.
- Stage text in the editor: each `*.stage.*` text has a `Slop.reveal` hook (`showAt`, just before `Slop.start`) that glides to the slide and build where it shows (the pure interval, the stack and pump modes come from the build), and back afterwards. A new stage text needs an entry there.
- Edit mode: From `vite-project/`: `npx slop-editor edit public/slop/play/comma-pump.html` (it picks a free port from 5178 and prints the link). The page links `/slop/slop.css` and `/slop/slop.js`, which come from the installed `slop-editor` package (see `../CLAUDE.md`). Never copy them into the page.

## Story (6 steps, 20 builds + appendix)

| Step (scene) | Builds |
|---|---|
| `hero` | front page; stage = static fifths spiral + enable-sound button |
| `pure` | octave / fifth / major third / piano (12-TET) third; waves, sum, overtone ladders with beat rates |
| `stack` | 12 fifths spiral / the Pythagorean gap (zoomed number line) / 3 thirds and the diesis |
| `pump` | chain (zoomed, first loop) / pure loop sinking / fixed-C mode (held A jumps 81/80) / equal temperament / why: (3/2)⁴ vs 2²·5/4 |
| `temper` | JI triad / meantone / 12-TET / meantone wolf / all keys (circle-of-fifths ring) |
| `lattice` | explore / the pump's path on the lattice |

The appendix (`#after`) is the final stop: intervals, commas, the five tunings and the sound notes, all generated by `appendix()`, plus further reading.

## Architecture

- **Math first** (top of the script): `Q` fractions; `PYTH`, `DIESIS`, `SYNT` (built as 4 fifths over 2 octaves and a third), `SCHISMA` and `GDIESIS`; `nameOf(k)` names notes on the line of fifths; `latQ(a, b)` gives the lattice pitch 3^a·5^b. `JI_PC` is just intonation's 12 notes, a 4×3 lattice block around C.
- **Pump**: `CHAIN` derives each chord's root from the common tone with the previous chord, so the final C comes out at 80/81 (`PUMP`). `CHAIN_FIX` roots every chord in `JI_PC`. `VOICING` keeps each shared tone in the same voice, so it is held. `JUMPS` finds the voice that must move in fixed-C mode. `pumpEvent(mode, k)` (modes `just`, `fixed`, `et`) gives frequencies, cents vs ET, and held/shift flags per voice. Playback uses four continuous oscillators (`pumpStart`/`pumpTick`, a lookahead scheduler). Moving notes re-articulate, held notes don't, and a shifted note slides with an exponential ramp. There is an optional reference-C drone and three tempos.
- **Tunings**: `TUNINGS[key].cents[pc]` and `.names[pc]`. `chainTuning(fifthSize(j))` builds Pythagorean, meantone, Werckmeister III and 12-TET from a chain of fifths E♭…G♯. `triadInfo(t, root)` and `worstFifth(t)` give sizes, offsets from pure and beat rates (gap between the nearest coinciding harmonics). `badness` colors the key ring.
- **Scenes**: `SC[scene] = {layer, set(build), frame(now), primary()}`. `primary` is what `P` plays. Stage layers are `.layer` divs, shown with `.on`. Leaving a scene calls `stopSequences()` (timers + registered stoppers such as `pumpStop`).
- **Navigation**: `stops` = every (step, build) plus the appendix. ←/→ glide-scroll with a sine ease, and the stage switches at once. On desktop, cards are sticky and show one build paragraph at a time. On phones (≤900px) the stage is pinned on top (58svh) and the text flows underneath: each build is its own paragraph, and the active build is the last paragraph above the read line (`detect`, `stopY`). This means text length can never overflow the screen.
- **Keyboard/a11y**: lattice nodes and key-ring wedges are `role=button` with `tabindex`, and Enter/Space activate them. `keepFocus` restores focus after an SVG re-render.

## Testing

- `python3 tools/check_numbers.py` renders the page and checks every `data-k` figure, the comma table and all 60 tuning cells against an independent Python computation (including published Werckmeister III values).
- `tools/smoke.sh` renders every stop at 1400×900 and 390×844 and reports script errors and console warnings, then drives every sound path once. It takes several minutes.
- `tools/render.sh NAME STOP [W,H] [JS]` takes one screenshot to `shots/NAME.png` (gitignored). It renders a copy of the page with slop-editor inlined from `node_modules` (`../page.py`), so run `npm install` first. The page has a `/* @render-hook */` marker in `frame()` that the script replaces to force a stop. Keep it. In the test copy rAF is driven by timers, because headless Brave doesn't fire it in the DOM-dump pass. Widths under 500px are shot through an iframe (Brave's minimum window width).
- Headless audio stays suspended, so sound is only checked for errors, never heard. Judge timbre, loudness and beating by ear in a real browser.
